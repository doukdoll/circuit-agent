# Python 파일로 규칙 DB 만들기

> 이전 JSON 전용 v7의 보존 문서입니다. 실행기는 tools/spdm_legacy_v7에 있으며 현재 버전은 [CSV+JSON/14테이블 안내](CIRCUIT_REVIEW_RUN.md)를 따릅니다.

작성일: 2026-10-19 / 실행 파일: setup_rules.py / DB 스키마: v7

## 1. 준비

- Python 3가 설치된 Windows PC와 사내 원본 규칙 JSON이 필요합니다.
- spdm-python-v7.zip을 탐색기에서 우클릭 → 모두 압축 풀기로 새 폴더에 풉니다.
- 압축 해제한 폴더에서 setup_rules.py가 보이는지 확인합니다. 같은 폴더에 json_rules.py, sqlite_store.py, import_rules.py, analysis.schema.json 등 동봉 파일을 함께 둡니다. 실행 파일 하나만 다른 폴더로 옮기지 않습니다.

SQLite는 Python에 포함되어 별도 설치하지 않습니다. pip·DB 서버·외부 API·PowerShell 명령 없이 사용할 수 있습니다. ZIP에 Python 설치 프로그램과 실제 JSON/DB는 포함하지 않습니다.

## 2. 실행

1. 탐색기에서 setup_rules.py를 더블클릭합니다.
2. **1. 원본 규칙 JSON 선택** 창에서 사내 JSON을 고르고 열기를 누릅니다.
3. **2. 규칙 DB 저장 위치 선택** 창에서 DB 파일명과 위치를 정하고 저장을 누릅니다. 기본 파일명은 rules-v7.sqlite입니다.
4. 이미 존재하는 DB를 선택했다면 **기존 규칙 전체 교체** 창이 나옵니다. 선택한 JSON 전체로 교체할 때만 예를 누릅니다. 아니오나 파일 선택 취소는 적재하지 않고 종료합니다.
5. 검사·적재가 끝나면 완료 창에서 체크포인트 수·세부 규칙 수·경고 수·DB 경로·보고서 경로를 확인합니다.

원본 JSON을 수정하지 않습니다. JSON 구조가 잘못되면 적재하지 않고 오류 경로와 사유를 표시합니다. 기존 DB를 갱신하다가 입력 오류나 SQL 오류가 나면 기존 데이터가 보존됩니다. 적재 보고서는 선택한 DB와 같은 폴더에 `<DB이름>_import_<시각>.json`으로 남습니다. 보고서에는 원본 미리보기가 포함될 수 있으므로 사내에서 관리합니다.

완료 창을 확인한 뒤 프로그램은 종료합니다. 다음에 실행할 때 JSON/DB를 다시 선택하며 서버를 실행하거나 자동으로 이전 선택을 재사용하지 않습니다.

## 3. 더블클릭했는데 편집기로 열리는 경우

.py 파일이 Python 실행 프로그램에 연결되어 있어야 더블클릭 실행됩니다. 연결 상태에 따라 다음 방법 중 하나를 사용합니다.

- setup_rules.py를 우클릭 → 연결 프로그램에서 설치된 Python을 선택합니다.
- Python의 IDLE에서 File → Open으로 setup_rules.py를 열고 Run → Run Module 또는 F5를 누릅니다.
- VS Code에서 setup_rules.py를 열고 설치된 Python 인터프리터를 선택한 뒤 Run Python File로 실행합니다.

Python을 설치할 때 Tcl/Tk 및 IDLE 옵션을 제외했다면 Python 설치 프로그램의 Modify에서 해당 옵션을 추가합니다. 이 실행기의 파일 선택 창은 표준 라이브러리 tkinter를 사용합니다. GUI 창이 없는 서버 환경에서는 기존 CLI 방식을 사용합니다.

## 4. 저장 위치와 기존 DB

spdm-python-v7.zip의 평평한 폴더에서 실행하면 그 폴더 아래 local-output을 기본 저장 위치로 제안합니다. 기존 팀 배포의 app/spdm_json 폴더에 실행기를 둔 경우에는 배포 루트의 local-output을 제안합니다. 실행기를 어디서 실행했는지가 아니라 실행기 파일이 놓인 위치를 기준으로 하며, 저장 창에서 다른 경로를 선택할 수도 있습니다. **완료 창에 나온 DB 경로가 실제 사용한 파일입니다.**

스키마와 파싱 규칙은 기존 v7과 같습니다. checkpoints/rules 두 업무 테이블의 ID는 AUTOINCREMENT이며 SEC를 원문 그대로 보존합니다. 최신 JSON 전체로 교체하므로 일부 규칙만 담긴 JSON을 선택하면 이전 DB의 나머지 규칙은 제거됩니다. 새 DB를 만들면 ID 번호도 새로 시작합니다.

지원하지 않는 이전 스키마 DB는 그대로 보존하고 거부합니다. 새 파일명을 선택해 다시 실행합니다. JSON·코드·계약 파일과 DB의 경로가 같으면 적재를 거부합니다. SQLite DB를 다른 프로그램에서 열어 두었다면 잠금이 해제된 뒤 실행합니다.

## 5. 결과 해석

- imported: 새 DB에 처음 저장했습니다.
- replaced: 같은 v7 DB의 기존 규칙을 최신 JSON 전체로 교체했습니다.
- 경고: 전처리 이슈 등 검토할 정보입니다. 회로 FAIL 판정 수가 아닙니다.
- DB 적재 완료 · 보고서 저장 오류: DB 반영은 끝났으나 보고서 파일 기록이 실패한 경우입니다. 이때 적재가 취소됐다고 해석하지 않습니다.

건수는 입력마다 달라집니다. 이 도구는 규칙 저장까지 담당하며 QCV/BOM 회로 사실 추출이나 Gemini PASS/FAIL 판정을 수행하지 않습니다.

## 6. 확인한 범위

Linux/Python 3.12.14에서 기존 검사·저장·조회 및 실행기 관련 테스트 총 34개를 통과했습니다. 실행기 테스트는 파일/메시지 선택 창을 가짜 응답으로 대체하고 실제 JSON과 SQLite 적재를 실행합니다. 생성·전체 교체·취소·원본/DB 경로 충돌·이전 버전 거부·입력 오류 시 기존 DB 보존·보고서 기록 실패를 확인합니다.

기존 v7 핵심 저장 코드는 앞서 Windows PowerShell 5.1/7에서 테스트 25개를 통과한 버전과 같습니다. 새 Python 실행기에서 실제 Windows 선택 창을 열고 마우스로 조작하는 검증은 아직 수행하지 않았으며 기존 Windows CI 결과를 새 실행기의 Windows 검증 결과로 표현하지 않습니다. 동봉 verify_environment.py는 실행하는 PC에서 현재 테스트와 전체 적재·조회 흐름을 확인하는 선택 도구입니다.
