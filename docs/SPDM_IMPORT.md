# SPDM 컬럼 선택·최소 정제·SQLite 저장 가이드

## 현재 담당 범위와 첫 단계

입력은 Rule generator가 이미 병합한 `spdm_checkpoint_merged_*.xlsx` 또는 별도 담당자가 정제 결과 컬럼을 추가한 xlsx입니다. 두 원본을 다시 병합하거나 문구를 해석·요약하는 기능은 이 도구의 범위에 포함하지 않습니다.

`tools/spdm_import/inspect_rules.py`와 `mapping.json`으로 컬럼 선택·최소 정제 결과를 점검하고, `import_rules.py`로 전체 행을 SQLite에 저장합니다. `query_rules.py`는 지정한 가져오기에서 SEC별 규칙을 조회합니다. 점검·저장은 같은 전체 행 파싱 코드를 사용합니다. 서버와 외부 API를 사용하지 않습니다. 실제 정제 결과 컬럼·사용 컬럼·행 선별 기준은 사내에서 매핑을 확인해야 합니다.

회사 xlsx는 현재 저장소에 없으며 실제 정제 결과 컬럼 이름도 미제공 상태입니다. 기본 매핑은 전달받은 23컬럼 명세에서 선택한 **초기 제안**입니다. 실제 데이터의 행 수 7,252와 부품 수 901을 고정된 성공 조건으로 사용하지 않습니다.

사용자는 사내 파일/프로그램 반출이 불가능하고 외부 개발 코드의 반입은 가능하다고 확인했습니다. 외부 개발과 테스트는 구조 명세·가상 데이터로 수행하고, 실제 파일·결과 보고서는 사내에서만 확인하는 흐름으로 진행합니다. 실제 파일이나 보고서의 외부 제공을 전제하지 않습니다. 전체 Java 저장소를 가져갈 필요 없이 `tools/spdm_import/`의 Python 코드·설정·테스트와 [독립 실행 안내](../tools/spdm_import/README.md)를 반입할 수 있습니다. Python과 `openpyxl`은 사내 환경에서 준비해야 합니다.

## 실행 (Windows PowerShell)

저장소 루트에서 실행합니다. Python 3와 로컬 환경에 설치된 `openpyxl`이 필요합니다. 사내 환경에서 패키지를 받기 위한 외부 연결은 요구하지 않습니다.

```powershell
python -c "import openpyxl; print(openpyxl.__version__)"

python .\tools\spdm_import\inspect_rules.py `
  "C:\Users\d7983.lee\Downloads\Data\spdm_checkpoint_merged_20261012_160751.xlsx" `
  --report .\output\spdm\inspection.json `
  --preview 20
```

파일이 다른 위치에 있거나 정제 완료 버전이면 첫 번째 인수에 해당 파일 경로를 지정합니다. `--mapping`을 생략하면 스크립트 옆의 `mapping.json`을 사용합니다. 다른 설정 파일은 `--mapping PATH`로 지정합니다. 매핑 JSON은 UTF-8 또는 UTF-8 BOM을 지원합니다.

`output/`은 Git에서 제외되는 로컬 결과 위치입니다. 입력 Excel은 수정하지 않습니다. 보고서에는 원문 일부가 포함되므로 실제 회사 입력의 보고서를 공개 샘플로 취급하지 않습니다.

## 먼저 확인할 보고서 항목

| 항목 | 확인할 내용 |
| --- | --- |
| `data_rows`, `empty_rows` | 완전히 빈 행과 데이터가 있는 행을 구분한 수 |
| `columns` | 모든 입력 컬럼의 열 위치·헤더·빈값/채워진 값 수 |
| `selected_fields` | 선택한 컬럼, 타입, 변환 후 값이 있는 행 수 |
| `valid_unique_sec_codes` | 현재 8자리 문자열 규칙을 통과한 고유 SEC 수 |
| `issues` | 원본 행 번호·필드·변환 오류 또는 범위 경고 |
| `duplicate_candidates` | 제안 키가 같은 행과 최초 행 번호; 삭제하지 않음 |
| `preview` | 최대 지정 행 수의 원본 행 번호와 선택된 원문/정제값 |
| `mapping_sha256` | 사용한 설정 내용의 식별 해시 |

미리보기 행 수와 무관하게 전체 데이터 행을 검사합니다. `--preview 0`으로 원문 미리보기 없이 통계·문제 목록만 만들 수 있습니다. 변환 오류의 `selected` 값은 `null`이고, 미리보기에 포함된 행은 `raw`와 `issues`로 원인을 확인합니다. 이 값으로 바로 DB를 저장하면 안 됩니다.

종료 코드 0은 점검이 완료되고 변환 오류가 없다는 뜻입니다. 경고와 중복 후보가 없다는 뜻은 아니며 회로 적합성 판정도 아닙니다. 종료 코드 2는 입력/설정 오류 또는 데이터 변환 오류입니다. 데이터 변환 오류가 있으면 보고서는 생성됩니다. 파일이나 헤더 구조를 읽지 못하면 보고서는 생성하지 않습니다. 실행 실패 후 예전 보고서를 이번 결과로 오인하지 않도록 종료 코드를 확인합니다.

## 저장 후보 컬럼과 매핑 변경

기본 후보는 부품/규칙 `adminno`·`seqno`, `sec_code`, `maker`, `maker_pn`, `Checkpoint`, `Specification`, `설계치`, `참조문서`, `category`, `pin_info`입니다. 작성자·LDRC·날짜 등 관리용 컬럼은 전체 통계에 보이지만 선택값에는 포함하지 않았습니다. 이는 필요성이 확정되지 않은 컬럼을 제외한 초기 제안이며, 관리 요구가 정해지면 설정에 추가합니다.

중복 헤더는 열 위치와 예상 헤더를 함께 확인합니다. 예를 들어 A/B는 부품 그룹 정보, H/I는 규칙 정보로 구분합니다. 실제 파일에서 열이 바뀌면 오류를 내므로 실제 매핑을 수정해야 합니다.

정제 담당자가 `Checkpoint_cleaned`라는 고유 컬럼을 추가했다고 가정하면, `checkpoint` 필드 설정을 다음처럼 바꿀 수 있습니다. 이 컬럼 이름은 사용법 설명을 위한 예시입니다.

```json
{"name": "checkpoint", "header": "Checkpoint_cleaned", "type": "text"}
```

`column`을 생략하면 고유 헤더로 찾습니다. 헤더가 중복되면 `column`도 지정해야 합니다. 선택한 정제 컬럼이 비어 있어도 원문 컬럼으로 자동 대체하지 않습니다. 원문과 정제 컬럼 둘 다 비교하려면 내부 이름이 다른 두 필드를 각각 등록합니다. 필드를 설정에서 제거하면 선택값과 이번 DB 적재값에서 제외됩니다. 기존 가져오기 데이터는 보존됩니다.

## 현재 적용하는 최소 정제

- `text`: 앞뒤 공백 제거, CRLF/CR 줄바꿈을 LF로 통일. 내부 공백·줄 구분·숫자·단위·조건·`|`·첨부파일 표현·핀 표현은 보존.
- 빈 셀/공백뿐인 값: `null`. `0`은 빈값으로 취급하지 않으며 선택 컬럼의 `N`도 보존.
- `sec_code`: 앞뒤 공백을 제외하고 ASCII 숫자 8자리 문자열인지 확인. 숫자 셀은 오류로 기록하며 임의의 0 패딩이나 대시 제거는 수행하지 않음.
- `integer`: 정수 또는 소수 부분이 없는 숫자, 정수 문자열만 허용. 소수·논리값은 오류.
- `datetime`: 선택했을 때 통합문서의 1900/1904 날짜 체계를 사용하고 시각을 포함한 ISO 문자열로 변환. 임의의 날짜 문자열 파싱은 하지 않음.
- `category`: `a/b/c` 이외의 값은 경고를 내고 값을 유지. 빈값은 허용.
- 수식·Excel 오류 셀: 선택한 컬럼에 있으면 오류. 계산하거나 오래된 캐시 값을 대신 사용하지 않음.

`Checkpoint` 빈값을 이유로 행을 삭제하거나 EN/KO 분리·핀 숫자 추출·문장 요약을 하지 않습니다. `설계치`는 규칙에 기록된 값으로 취급하며 특정 보드의 관측값으로 간주하지 않습니다. `required`는 현재 식별 컬럼에만 적용했습니다.

중복 후보 키 `[sec_code, rule_adminno, rule_seqno]`는 점검용 제안입니다. DB에서는 같은 키의 모든 행을 보존하며 `(batch_id, source_row)`로 입력 행을 구분합니다. 규칙의 업무 유일 키는 아직 확정하지 않았습니다.

## SQLite 적재와 규칙 조회

저장소 루트에서 실행합니다. 독립 반입 폴더에서의 명령은 [반입 안내](../tools/spdm_import/README.md)에 있습니다.

```powershell
python .\tools\spdm_import\import_rules.py `
  "C:\Users\d7983.lee\Downloads\Data\spdm_checkpoint_merged_20261012_160751.xlsx" `
  --db .\output\spdm\rules.sqlite `
  --report .\output\spdm\import-result.json

python .\tools\spdm_import\query_rules.py .\output\spdm\rules.sqlite `
  --batch-id 1 --sec-code "03438806" `
  --output .\output\spdm\matched-rules.json
```

조회의 `batch-id`는 실제 적재 결과로 받은 ID를 사용합니다. SEC는 입력의 대시 없는 8자리 문자열로 조회하고 임의의 BOM 코드 변환은 하지 않습니다. 가져오기 선택을 필수로 하여 서로 다른 규칙 버전이 섞이지 않도록 했습니다. 규칙 미매칭은 `NOT_FOUND`/종료 코드 3이며 PASS가 아닙니다. 조회 오류는 2, 매칭은 0입니다.

| 테이블/필드 | 역할 |
| --- | --- |
| `import_batches` | 원본 파일명·바이트 해시, 매핑 내용·해시, 파서/적재 버전, 시트명, UTC 적재 시각, 행 수, 점검 보고서 |
| `rules` 기본 컬럼 | 기존 13개 선택 필드; `sec_code` TEXT, 번호 INTEGER, 문장 TEXT |
| `rules.raw_json` / `selected_json` | 매핑에 선택된 전체 원문/정제값; 추가 전처리 컬럼도 JSON으로 저장 |
| `rules.batch_id` / `source_row` | 규칙 버전과 원본 행 추적; `(batch_id, sec_code)` 인덱스로 부품별 조회 |
| `rules.issues_json` / `duplicate_first_row` | 분류 경고·중복 후보의 최초 행 위치 보존 |

행 저장은 미리보기 개수에 제한되지 않습니다. 완전히 빈 행만 건너뛰고, 빈 Checkpoint·중복 후보·경고 행은 보존합니다. 변환 오류 또는 저장 오류가 있으면 이번 가져오기의 테이블 생성·이력·규칙 삽입을 트랜잭션으로 모두 취소합니다. 기존 데이터는 유지하며 처음 실패한 경우 내용 없는 DB 파일이 남을 수 있습니다. 다른 용도의 SQLite나 미지원 버전의 DB에는 적재하지 않습니다.

동일 파일 바이트·매핑·파서/적재 버전의 재실행은 `skipped`와 기존 가져오기 ID를 반환합니다. 입력/설정이 바뀌면 새 가져오기를 생성하고 기존 데이터는 덮어쓰지 않습니다. 입력 파일은 한 번 읽은 동일 바이트로 해시·파싱하여 실행 중 파일 변경으로 해시와 저장값이 어긋나지 않도록 합니다. 보고서 경로는 선택 사항이며 DB 커밋 후 보고서 쓰기만 실패하면 적재 완료 ID를 오류 메시지로 알려줍니다.

QCV 부품 참조번호 → BOM SEC → `lookup_rules(database, sec_code, batch_id)` 순서로 규칙을 찾는 인터페이스를 준비했습니다. QCV/BOM 파싱·코드 변환·판정은 아직 연동하지 않았습니다. 규칙의 설계치는 규칙에 기록된 값으로 보관하고, 보드 참조번호·실제 회로값·판정 결과는 별도 검증 단계의 책임으로 둡니다.

## 다음 작업

1. 코드·설정·테스트를 반입하여 가상 데이터 테스트를 실행한 뒤, 실제 병합/정제 완료 파일에 점검을 실행하고 사내에서 헤더·통계를 확인합니다.
2. 긴 문장·단위·빈값·EN/KO 혼합·핀 표현을 포함한 대표 행의 원문/정제값을 비교합니다. 미리보기는 처음 N개 데이터 행이며 대표 표본 자동 추출 기능은 아닙니다.
3. 사내 전처리 담당자와 사용할 결과 컬럼 이름, 빈 정제 결과의 처리, 제외 조건, 식별 키를 확정합니다. 원본·보고서는 사내에 유지하며 후속 개발은 공유 가능한 명세 또는 가상 재현 사례로 검증합니다.
4. 사내에서 확정한 매핑으로 SQLite에 적재하고 결과 행 수·원문 추적·SEC별 조회를 확인합니다. 이후 QCV 참조번호와 BOM의 연결, SEC 코드 형식, 규칙/회로 사실의 검증기 전달 형식을 확정하여 연동합니다.

NASCA DRM 해제 기능은 구현하지 않았습니다. `openpyxl`이 읽을 수 있는 입력을 전제로 하며 DRM 환경에서의 실제 동작은 별도 확인이 필요합니다.

## 개발 검증

```powershell
python -m unittest discover -s tools/spdm_import -p "test_*.py" -v
```

첫 점검 버전에서는 가상 xlsx 테스트 11개가 통과했습니다. SQLite 확장 작업에서는 2026-10-14 관리 Linux 환경(Python 3.12.14, openpyxl 3.1.5)에서 전체 25개 테스트가 통과했습니다. 기존 파싱 검증과 함께 미리보기 밖 전체 행 적재·원문/타입·빈값/중복/경고 보존·설정/파일 변경별 가져오기 분리·동일 입력 스킵·변환 및 SQL 오류 시 전체 롤백·읽기 전용 SEC 조회·미매칭·경로 충돌·타 DB 거부를 검증했습니다. Windows 및 실제 회사 입력/DRM 검증은 수행하지 않았습니다. 기존 Java 테스트를 이번 작업에서 재실행하지 않았습니다.
