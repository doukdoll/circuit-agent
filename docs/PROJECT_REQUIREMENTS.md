# circuit-agent 프로젝트 요구사항 정리

> 사용자가 제공한 프로젝트 설명을 기반으로 작성한 초기 요구사항 문서입니다.
> 원본 데이터시트, QCV, BOM을 확인하지 않았으므로 예시 수치와 PASS 판정은 검증된 결과가 아닙니다.

## 1. 프로젝트 개요

- **프로젝트명:** CircuitAgent
- **저장소명 후보:** `circuit-agent`
- **목표:** 반도체 데이터시트에서 설계 규칙을 추출하고, 실제 회로의 연결 구조와 부품 사양을 분석해 규칙 준수 여부를 자동으로 검증한다.
- **대상 사례:** 5G 기지국 통신장비 P4452D-03A의 전원 회로
- **핵심 구성:** Rule Generator Agent + Rule Checker Agent + 수치 계산 엔진 + 자동 보고서 생성

쉽게 말해, 사람이 데이터시트를 읽고 회로도와 부품표를 대조하며 계산하던 회로 Audit 업무를 자동화하는 시스템이다.

## 2. 해결하려는 문제

1. 수백 페이지의 데이터시트에서 핀 제한, 권장 부품값, 계산 공식을 수작업으로 찾는 데 시간이 많이 든다.
2. 규칙을 엑셀로 옮기거나 실제 회로와 대조하는 과정에서 누락과 입력 오류가 발생할 수 있다.
3. 연결 관계 검사 외에 저항비에 따른 출력 전압, 핀 과전압, 커패시터 실효 용량 등의 수치 검증이 필요하다.
4. 제작 이후 오류를 발견하면 보드 재제작과 개발 일정 지연이 발생할 수 있다.

원문은 기존 EDA 검사의 한계를 강조한다. 다만 EDA 제품마다 지원 기능이 다르므로, 특정 도구가 수치 검증을 지원하지 않는다는 주장은 별도 확인이 필요하다.

## 3. 전체 처리 흐름

```text
반도체 데이터시트 PDF
        ↓
[Stage 01] Rule Generator: 규칙 추출 및 구조화
        ↓
설계 규칙 JSON / Excel
        ↓
[Stage 02] Design Modeling: QCV 연결 구조 + BOM 사양 모델링
        ↓
회로 그래프 및 정규화된 부품 정보
        ↓
[Stage 03] Rule Checker: 규칙 적용 및 수치 계산
        ↓
판정 / 계산값 / 근거 / 확인 필요 항목
        ↓
[Stage 04] Audit Automation: 검증 보고서 생성
```

## 4. 입력 데이터

| 입력 | 용도 | 확인할 사항 |
|---|---|---|
| 반도체 데이터시트 PDF | 핀 제약, 공식, 권장 부품 사양 추출 | 정확한 모델명, 문서 버전, 표·그림·수식의 추출 가능 여부 |
| EDA 넷리스트 `.qcv` | 부품·핀·넷 연결 관계 분석 | 실제 파일 문법과 핀 번호 매핑 |
| BOM | 부품별 모델명과 저항·용량·내압·공차 확인 | 파일 형식, 컬럼 구조, RefDes와 파트넘버 매핑 |
| 설계 목표 및 동작 조건 | 계산 결과를 목표값·허용오차와 비교 | 출력 목표 전압, 입력 범위, 동작 모드, 주파수 등 |
| 부품 특성 자료 | MLCC 실효 용량 등 특성 기반 계산 | 제조사 DC Bias 곡선 등 추가 자료의 제공 여부 |

데이터시트에 적힌 일반적인 제한과 해당 보드가 의도한 목표값은 구분한다. 예를 들어 출력 목표가 3.7V라는 사실은 설계 정보에서 확인해야 한다.

## 5. Agent 1: Rule Generator

### 목적

비정형 데이터시트에서 설계 제약과 권장 사항을 추출해 기계가 검사할 수 있는 규칙으로 변환한다.

### 주요 기능

1. 데이터시트의 Pin Functions, Recommended Operating Conditions, Absolute Maximum Ratings, Application Information 등의 관련 섹션을 탐색한다.
2. 핀별 전압 제한, 계산 공식, 외장 RLC 사양 및 적용 조건을 추출한다.
3. 단위와 부품 명칭을 정규화한다.
4. Mandatory, Schematic Rule, Layout 등의 분류로 규칙을 구조화한다.
5. 규칙 JSON과 검토용 Excel을 생성한다.
6. 각 규칙에 원문 페이지·표·문구 등 출처를 연결한다.

### 원문에 제시된 규칙 예시

- EN 핀 전압 제한: `V_EN ≤ 3.6V`
- 출력 전압 계산: `V_OUT = 0.6 × (1 + R_upper / R_lower)`
- 입력 커패시터 요구량: `C_IN ≥ 40μF`
- 동작 모드 및 주파수 조건: `FCCM_1MHz`

위 값은 원문 예시이며, 실제 적용 전 대상 칩의 데이터시트와 동작 조건을 확인해야 한다. 권장 동작 범위와 절대최대정격도 별도로 관리한다.

### 원문 Rule JSON 예시

```json
{
  "rule_id": "RULE_10_FB_DIVIDER",
  "category": "Mandatory",
  "target_pin": "FB (Pin 14)",
  "formula": "0.6 * (1 + R_upper / R_lower)",
  "tolerance": 0.03,
  "required_mode": "FCCM_1MHz"
}
```

이 JSON은 개념 설명용 샘플이다. 핀 번호, 공식 계수, 허용오차의 출처와 `cp-v1` 전체 스키마는 별도 확인이 필요하다. 구현 시 대상 부품, 적용 조건, 단위, 출처, 미확정 정보도 표현할 수 있어야 한다.

## 6. Agent 2: Rule Checker

### 목적

생성된 규칙을 실제 회로 연결과 BOM 사양에 적용해 수치 검증 및 판정을 수행한다.

### 주요 기능

1. QCV에서 부품·핀·넷 관계를 파싱해 회로 그래프를 만든다.
2. BOM의 RefDes와 넷리스트 부품을 연결한다.
3. 제조사별 파트넘버 또는 명시된 사양에서 저항값, 공차, 정전용량, 내압 등을 읽어 표준 단위로 변환한다.
4. FB 핀 주변의 상부·하부 저항, 피드포워드 커패시터 등 검증 대상 부품을 식별한다.
5. EN 제어망, 입력·출력 커패시터 어레이 등 관련 연결을 추적한다.
6. 계산 엔진으로 수치를 계산하고 규칙의 기준과 비교한다.
7. 판정 근거와 엔지니어 확인이 필요한 기술 의견을 생성한다.

파트넘버만으로 확인할 수 없는 사양이나 해석이 모호한 연결은 임의로 확정하지 않는다. LLM의 문서 해석과 수치 계산 엔진의 결과를 구분해 추적할 수 있어야 한다.

### 주요 검증 항목

| 항목 | 검사 내용 | 필요한 정보 |
|---|---|---|
| FB 저항 분배 | 계산된 출력 전압과 목표 전압의 오차 | 공식, 저항쌍, 목표 전압, 허용오차 |
| EN 안전 전압 | 제어 핀에 허용 범위를 넘는 전압이 인가되는지 | 연결망, 신호 전압, 핀 제한 |
| 입력 커패시터 | 요구 용량과 내압 충족 여부 | 연결된 커패시터, 부품 사양, 입력 조건 |
| 출력 MLCC | 동작 조건에서 실효 용량이 충분한지 | 병렬 어레이, DC Bias 등 특성, 출력 조건 |
| 소프트스타트 | SS 커패시터에 따른 기동 시간 | SS 공식, 커패시터값, 요구 시간 |
| 인덕터 | 대상 동작 조건에 적합한 사양인지 | 인덕턴스, 정격, 대상 칩 요구조건 |
| BST 구성 | 부트스트랩 관련 부품과 연결의 적합성 | 저항·커패시터 사양, 연결, 데이터시트 기준 |
| MODE 설정 | 저항 구성에 따른 모드·주파수 적합성 | 설정 저항, 모드 매핑, 요구 동작 조건 |
| 피드포워드 커패시터 | 연결 및 권장값 적합성 | Cff 연결, 용량, 적용 조건 |
| PG 구성 | 풀업 전압·저항과 감지망 적합성 | PG 핀 제한, 풀업 사양, 연결 |

MLCC 실효 용량은 명목 용량을 단순 합산한 값과 구분한다. QCV와 BOM만으로 확인할 수 없는 동작 특성은 추가 자료 또는 엔지니어 확인이 필요하다.

### 수치 검증 예시: U37

원문에 제시된 목표 전압과 공식, 저항값을 사용하면 다음과 같다.

```text
목표 출력 전압 = 3.7V
상부 저항 = 52.3kΩ
하부 저항 = 10.0kΩ

V_OUT = 0.6 × (1 + 52.3 / 10.0)
      = 3.738V

목표 대비 오차 = (3.738 - 3.7) / 3.7 × 100
              ≈ +1.03%

허용 기준이 ±3%라면 명목값 기준 PASS
```

이 예시는 저항과 기준 전압의 공차를 포함한 최악 조건 검증 결과가 아니다. 공차까지 검증할지는 별도 요구사항으로 확정한다.

## 7. 출력 및 판정 방식

### 출력물

- 추출된 설계 규칙 JSON
- 규칙 검토용 Excel
- 인스턴스별·규칙별 검증 결과
- 사용한 부품값, 계산식, 계산 결과, 기준값, 출처
- 확인 필요 항목과 H/W Confirm 기술 의견
- 회로 Audit 보고서

### 제안하는 판정 상태

| 상태 | 의미 |
|---|---|
| PASS | 필요한 정보가 확보됐고 해당 규칙을 충족함 |
| FAIL | 해당 규칙을 위반함 |
| NEEDS_REVIEW | 정보 부족 또는 해석 모호성으로 자동 판정할 수 없음 |
| NOT_APPLICABLE | 해당 인스턴스 또는 동작 조건에 적용되지 않는 규칙 |

입력 파일 파싱 실패나 계산 오류는 별도 오류로 기록한다. 미검증 항목이 있는 인스턴스를 전체 PASS로 표시하지 않으며, 보고서에 검증 완료·미완료 범위를 표시한다.

## 8. 원문에 제시된 회로 사례

| 인스턴스 | 용도 / 출력 레일 | 모델 | 원문에서 제시한 주요 결과 |
|---|---|---|---|
| U24 | Versal FPGA Core / 0.8V_FPGA | TPS56C230RJER | 입력 용량 44.1μF, SS 4.0ms, 출력 실효 용량 505.2μF |
| U37 | Clock & Analog / 3.7V | TPS568230RJER | 계산 전압 3.738V, 오차 +1.03%, 1MHz FCCM |
| U56 | RFIC Digital Core / 1.0V_RFIC_VDD_STAT | TPS568230RJER | 1.8V GPIO EN 제어, SS 12.0ms, 1MHz FCCM |
| U60 | RFIC Analog / 1.8V_RFIC_VDD | TPS568230RJER | 1.8V GPIO EN 제어, SS 12.0ms, 1MHz FCCM |

원문은 네 인스턴스를 모두 FULL PASS로 표시한다. 이 문서는 해당 사례를 옮겨 정리한 것이며, 실제 부품 연결·사양·판정을 재검증한 보고서는 아니다.

## 9. 원문에 제시된 기술 및 연동

| 기술 / 포맷 | 제시된 용도 | 현재 확인 상태 |
|---|---|---|
| Gemini Agent | 데이터시트 해석 및 규칙 추출 | 모델·API·실행 환경 미확정 |
| NASCA DRM PDF Stream | 사내 보안 PDF 입력 | 승인된 문서 접근·복호화 연동 방식 확인 필요 |
| cp-v1 JSON | 설계 규칙 교환 포맷 | 전체 스키마 미제공 |
| openpyxl | 규칙 Excel 출력 | 구체적인 엑셀 양식 미제공 |
| QCV Parser | 넷리스트 파싱 | 샘플 파일·문법 미제공 |
| BOM Decoder | 제조사 부품 코드 해석 | 지원 제조사 및 파트넘버 범위 확인 필요 |
| Topology Graph | 회로 연결 추적 | 그래프 모델 및 탐색 방식 미확정 |
| Numerical Engine | 공식 계산과 기준 비교 | 계산 범위 및 공차 처리 방식 미확정 |

사내 문서 처리는 조직에서 허용한 접근·복호화·외부 모델 전송 범위 안에서 설계한다.

## 10. 초기 구현 범위 제안

다음은 원문 요구를 구현 가능한 단계로 나누기 위한 제안이며, 확정된 개발 범위는 아니다.

1. **입력 모델 검증:** 대상 칩 하나와 회로 인스턴스 하나를 선정해 PDF·QCV·BOM 연결을 확인한다.
2. **핵심 규칙 구현:** FB 출력 전압, EN 전압, 입력 커패시터 사양부터 검증한다.
3. **근거 포함 보고서:** 규칙 출처, 부품 매핑, 계산 과정, 판정을 출력한다.
4. **검증 범위 확대:** SS, MODE, PG, BST, 출력 MLCC 등으로 확장한다.
5. **복수 인스턴스 검증:** U24·U37·U56·U60 등 여러 전원 회로를 일괄 처리한다.

Layout 규칙의 추출과 검증은 구분한다. 실제 배치·배선 검증에는 QCV·BOM 외에 PCB 레이아웃 자료가 필요할 수 있으므로 별도 범위를 정의한다.

## 11. 검증 기준 제안

- 추출한 규칙이 원본 데이터시트의 수치, 단위, 조건, 출처와 일치한다.
- 알려진 샘플 회로에서 핀·넷·부품 연결과 BOM 매핑이 정확하다.
- 계산값과 판정이 엔지니어가 확인한 기준 결과와 일치한다.
- 의도적으로 저항값이나 EN 연결을 바꾼 오류 사례를 검출한다.
- 누락된 BOM 사양이나 모호한 연결을 PASS로 처리하지 않는다.
- 동일한 입력과 규칙 버전으로 수치 검증 결과를 재현할 수 있다.
- 처리 시간은 PDF 분석, 모델링, 규칙 실행, 보고서 생성을 구분해 측정한다.

## 12. 추가로 확인해야 할 사항

1. 원본 데이터시트, QCV, BOM 샘플과 파일 형식
2. 우선 지원할 반도체와 제조사 부품 코드 범위
3. `cp-v1` 스키마와 원문에 언급된 22개 체크포인트의 전체 목록
4. 각 규칙의 근거, 적용 조건, 필수 여부 및 허용오차
5. 설계 목표 전압·제어 신호 전압 등의 입력 방법
6. MLCC 특성 자료의 확보 방법과 실효 용량 계산 기준
7. 명목값 검증과 공차·최악 조건 검증의 범위
